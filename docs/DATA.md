# Языковые данные

В приложении три вида данных о языке. Сетью оно не пользуется: всё лежит в бандле.

| Что | Где | Откуда |
| --- | --- | --- |
| Орфографические словари | `Sources/LangSwitchLexicon/Resources/Hunspell` | LibreOffice (RU, 146 тыс. основ) и SCOWL (EN, 48 тыс. основ); с аффиксами — миллионы словоформ |
| Ядро частотного списка | `Resources/Frequency/ru.txt`, `en.txt` | составлено для проекта: 5 245 и 3 372 самые употребительные формы |
| Расширение частотного списка | `Resources/Frequency/ru-extended.txt`, `en-extended.txt` | **сгенерировано**: 118 668 и 39 584 формы по убыванию частоты |
| Модель контекста | `Resources/Context/ru.pairs`, `en.pairs` | **сгенерировано**: 406 и 489 тыс. пар соседних слов, 2,6 и 2,3 МБ |
| Политика исправлений | `Resources/Rules/correction-policy.json` | **обучено** на корпусах из `Tests/LangSwitchLexiconTests/Fixtures` |

## Как это собрано

```
./scripts/fetch-language-data.sh                       # исходные файлы в .build/data
swift run -c release LangSwitchData .build/data .       # списки, модели контекста, тестовые корпуса
LANGSWITCH_ANALYSIS=/tmp/analysis.tsv swift test -c release -Xswiftc -enable-testing --filter corpusAnalysis
python3 scripts/train-correction-policy.py /tmp/analysis.tsv --write --threshold 0.78
./scripts/check.sh
```

**Расширение частотного списка.** Слово из субтитров попадает в список, если его знает орфографический
словарь и оно встречается не реже 0,13 раза на миллион. Слово, которого словарь не знает (имя,
разговорная форма, британское написание), должно встречаться не реже 2 раз на миллион **и** не менее
пяти раз во втором корпусе, написанном и вычитанном людьми. Согласие двух независимых корпусов и
отличает слово от ошибки: `favourite` (11 650 раз в субтитрах, 634 в предложениях) и «ща» (451 и 6)
есть в обоих, а «вобщем» (428 и 0), «агенство» (455 и 0), `dont` (9 523 и 3) часты в субтитрах и почти
отсутствуют в предложениях; мусора распознавания во втором корпусе нет вовсе. Ядро списка остаётся
первым и не меняется: на нём откалиброваны решения о раскладке.

**Модель контекста.** По предложениям Tatoeba считается, сколько раз одно слово следует за другим; пары,
встреченные один раз, отбрасываются. Слова хранятся номерами в частотном списке, в файле записана
подпись списка — модель, собранная под другой список, не загрузится (тест `generatedDataIsInPlace`).
Каждое 25-е предложение в модель не входит: из них сделаны тестовые корпуса.

**Политика исправлений.** Модель ошибок предлагает замену; политика решает, применять ли её без
спроса. Это логистическая оценка по признакам предложения — вид правки, частотность слова, сила его
связи с предыдущим словом (во сколько раз чаще случайного они стоят рядом: частые слова следуют за чем
угодно, поэтому сам факт соседства ничего не доказывает), насколько далеко следующее объяснение, длина,
правдоподобие набранного, — а не по конкретным словам. Знаки весов ограничены: довод «за» не может работать «против». Каждая пятая
строка корпусов в обучение не идёт, и скрипт печатает результат именно на них.

## Тестовые корпуса

`Tests/LangSwitchLexiconTests/Fixtures` — в приложение не входят.

| Файл | Что это | Происхождение |
| --- | --- | --- |
| `typos-ru.tsv`, `typos-en.tsv` | 2 298 и 1 363 орфографические ошибки с правильным написанием | составлены для проекта |
| `colloquial-ru.txt` | 9 003 разговорные словоформы, которых нет в словарях | составлен для проекта |
| `sentences-ru.txt`, `sentences-en.txt` | по 1 500 предложений, не вошедших в модель контекста | Tatoeba, CC BY 2.0 FR |
| `unlisted-ru.txt`, `unlisted-en.txt` | 802 и 2 052 слова, которые люди пишут, а словари не знают | Tatoeba, CC BY 2.0 FR |

Опечатки для предложений создаются в тестах генератором с фиксированным зерном: пропуск, перестановка,
удвоение, соседняя клавиша вместо нужной или вместе с ней.
